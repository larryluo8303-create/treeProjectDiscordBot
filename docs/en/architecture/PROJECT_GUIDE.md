## 1. Design rationale

### What problem does this solve?

You run a large Discord stock/signal community where members ask questions around the clock. The channel owner cannot be online 24/7, but still wants:

1. **Automatic replies** that sound like their own tone and views (not generic AI finance boilerplate)
2. **Uncertain answers** to go through human review first — avoid wrong answers and invented entry points
3. **A knowledge base that keeps growing** (owner posts, approved reviews, YouTube transcripts, etc.)
4. **Ops automation**: daily/weekly summaries, Jin10 flash news, video digests, promo scheduling, new-member conversion

While also handling rate limits, spam/scam filtering, off-topic control, and keeping OpenAI cost and latency under control.

### Why RAG instead of fine-tuning?

| Approach | Pros | Issues for this project |
|---|---|---|
| Fine-tuning | Tone can be baked into weights | Views change daily; every new batch needs retraining; expensive and slow to iterate |
| **RAG (this project)** | New posts usable as soon as ingested; answers are traceable to history; easy to shut off / canary | Depends on retrieval quality and prompt constraints |

Conclusion: **store your historical content in ChromaDB + have GPT answer under a style guide**. Style comes from `data/style_profile.txt` (generated by `ingestion.analyze_style`), not from changing model weights. Early planning also explicitly deferred “fine-tune first”.

### Four core design principles

1. **Retrieval-augmented, not invented**  
   Embed and retrieve relevant history before generating. If retrieval is empty or distances are too far, hand off to the owner rather than forcing an answer.

2. **Triple confidence gate, conservative by default**  
   LLM self-score `CONFIDENCE: 1–10` (default threshold 7) + retrieval quality (no context / `best_distance` too large) + hard domain rules (e.g. “can I enter now / give me a level” signal questions always go to review — the Bot cannot see the live tape).

3. **Human-in-the-loop keeps getting sharper**  
   - Owner posts / voice in target channels → auto-ingest  
   - Review Approve / Edit → Q&A ingested  
   - Reject → negative samples injected into later system prompts  
   - Member 👍👎, Edit → feedback and knowledge-gap learning queue  

4. **Capabilities are switchable and canary-able**  
   Most subsystems default off (Jin10, YouTube, daily/weekly summaries, AutoMod, Admin, etc.) and turn on via env; new capabilities also use Feature Flags + per-channel Canary to avoid whole-server blowups.

### Answer boundaries (deliberate non-goals)

- **Do not pretend to see the tape**: signal / entry-timing questions always go to Owner review.  
- **Do not interrupt chitchat**: default `RESPOND_MODE=questions` — only questions, @Bot, replies to Bot, images/voice, etc.  
- **Do not inject promo copy randomly**: purchase intent takes a separate CTA path, split from RAG.  
- **Price levels are redacted**: dangerous price wording is redacted after generation; optional Safety Guardrails (force review or add disclaimer).

### Core Q&A flow

```
Member asks: "What do you think of AAPL?"
       ↓
① on_message pre-checks
   · Target channel? Excluded channel? Bot? Courtesy/spam/external links?
   · Owner post → learn/ingest only; skip Q&A
   · Purchase intent → product CTA (skip RAG)
   · Rate limit (VIP role may be exempt) → async queue
       ↓
② Single-threaded queue worker (avoid API storms / out-of-order replies)
   · Thread / recent conversation memory; Session summary if too long
   · Voice → Whisper; image → Vision (optional small retrieval context)
       ↓
③ RAG
   · Embedding → ChromaDB top-k → distance filter
   · System: style guide + negative-sample hints
   · User: retrieved snippets + conversation history + question
   · Output answer + CONFIDENCE
       ↓
④ confidence.route_answer
   · Passes → auto-reply in channel (optional low-frequency CTA)
   · Fails / signal question / no context → Owner DM review
       ↓
⑤ Closed loop
   · Approve/Edit → ingest; Reject → negative sample
   · 👍👎 → feedback; gaps → learning_queue
```

### How knowledge becomes “like you”

```
Historical Discord export / incremental ──► ingestion.ingest ──► ChromaDB
Owner daily posts / voice              ──► listener live learn ──► ChromaDB
Approved review Q&A                    ──► review ingest       ──► ChromaDB
YouTube transcripts (optional)         ──► ingest_youtube      ──► ChromaDB
Style analysis                         ──► analyze_style       ──► style_profile.txt
Rejected bad answers                   ──► negative_samples    ──► next prompt constraints
```

### Layered overview

```

│ Interaction layer                                                 │

└───────────────────────────────┬─────────────────────────────────┘
                                ↓
┌─────────────────────────────────────────────────────────────────┐
│ bot/main.py startup & assembly                                    │
│  Validate config → OpenAI client → ChromaDB → register Cogs →    │
│  bot.start(); optional WebhookServer / AdminServer / FastAPI     │
└───────┬─────────────────┬──────────────────┬────────────────────┘
        ↓                 ↓                  ↓
  MessageListener    Timed/poll Cogs    Slash Commands
  (Q&A main path)   (news/video/digest) (ops & growth)
        ↓
┌─────────────────────────────────────────────────────────────────┐
│ Intelligence core                                                 │
│  rag.py retrieve+generate · confidence.py route · review.py      │
│  feedback / feedback_learning · feature_flags · reliability      │
└───────────────────────────────┬─────────────────────────────────┘
                                ↓
┌─────────────────────────────────────────────────────────────────┐
│ Data & external services                                          │
│  ChromaDB(discord_posts) · data/*.json state files                │
│  OpenAI(Chat/Embed/Vision/Whisper) · Jin10 Flash · YouTube RSS    │
└─────────────────────────────────────────────────────────────────┘
```

### Startup sequence (`bot/main.py`)

1. `_validate_config()`: at least `DISCORD_BOT_TOKEN`, `OPENAI_API_KEY`  
2. Create `openai.AsyncOpenAI` (timeout/retry wrapped again at the RAG layer)  
3. Inject OpenAI into ban-words / Topic Guard; load `ban_words`  
4. `chromadb.PersistentClient(CHROMADB_PATH)` → collection `discord_posts` (cosine) → `AsyncCollection` wrapper  
5. Create Discord Bot (needs `message_content` / `members` / `invites` intents)  
6. Register `on_ready` (guild-level + global Slash sync)  
7. **Load Cogs in order** (see table below)  
8. Start Webhook / Admin HTTP / FastAPI per switches  
9. `bot.start(...)`; process signals trigger graceful unload

After `MessageListener` is ready it also: starts the message-queue worker, optional offline backfill, and periodic flush of `last_seen`.

### Main Cogs loaded at startup

| Order | Cog | Role |
|---|---|---|
| 1 | `MessageListener` | Channel listen, RAG Q&A, offline backfill, learn Owner posts |
| 2–3 | `PromotionCommands` / `BotCommands` | Slash: promotion + ops |
| 4 | `SchedulerCog` | Promo / lessons / reminders / FAQ push / SLA tick |
| 5 | `HealthCog` | Health and status |
| 6 | `IngestionSchedulerCog` | Periodically run `ingestion.ingest` + `analyze_style` |
| 7 | `DigestCog` | Channel activity digest (optional) |
| 8 | `NewsFeedCog` | Jin10 flash poll + offline backfill |
| 9 | `YouTubeMonitorCog` | New videos → schedule / ingest / summary |
| 10 | `AcquisitionCog` | Welcome drip, invite tracking |
| 11 | `PromoMonitorCog` | Source-channel activity → auto-schedule promos |
| 12–13 | `WeeklySummaryCog` / `DailySummaryCog` | Weekly/daily highlight summaries |
| 14 | `AutoModCog` | Spam/scam, ban words, topic limits |

### Q&A main path (detailed)

```
Discord on_message
    │
    ├─ Owner text/voice (target channel) → learn/ingest → return
    ├─ Update last_seen; keyword alerts / testimonial collection (side paths)
    ├─ _should_skip (bots, excluded channels, courtesy, spam, non-question mode, etc.)
    ├─ Rate limit (non-VIP) → asyncio.Queue
    ↓
Single worker _handle_message
    · Assemble Thread / channel conversation memory (optional Session summary)
    · Voice Whisper / image Vision
    · Purchase intent? → CTA Embed + funnel events + notify Owner (skip RAG)
    ↓
run_rag_pipeline (rag.py)
    · embed question → query Chroma top_k → drop distance > RAG_MAX_DISTANCE
    · No hits → fixed “uncertain” copy + low confidence
    · Hits → GPT generate (style + negatives + history) → parse CONFIDENCE → price redaction
    ↓
route_answer (confidence.py)
    · Signal question / no context / distance too bad / score below threshold → forward_to_owner
    · Else auto_reply (may still be rewritten by Guardrails / Clarification)
    ↓
auto_reply → channel reply + optional CTA + notify Owner (FYI DM)
  or
send_for_review → Owner DM buttons + review_queue.json + (optional) WebSocket to admin
```

### How RAG and confidence work together

| Stage | Key config / behavior |
|---|---|
| Retrieval | `EMBEDDING_MODEL` (default `text-embedding-3-small`), `RAG_TOP_K` (default 8), `RAG_MAX_DISTANCE` (default 0.6) |
| Generation | `LLM_MODEL` (default `gpt-4o-mini`); Vision uses `VISION_MODEL` (default `gpt-4o`) |
| Style | `style_profile.txt`, cache TTL ~5 minutes |
| Self-score | Trailing `CONFIDENCE: N`; parse failure treated as score 3 |
| Routing | Default `CONFIDENCE_THRESHOLD=7`; `best_distance > 0.95` still reviews even if score is high; `context_count==0` reviews |
| Clarification | `FEATURE_CLARIFICATION_FOLLOWUP`: low confidence that would still auto-reply can become a clarifying follow-up |

| Type | Content |
|---|---|
| Discord | Gateway, messages, DMs, Slash, roles/invites, attachments |

### Admin and client surfaces (optional)

|---|---|---|

## 4. Core module notes

### Config and entrypoint

**`bot/config.py`** — reads all switches and thresholds from `.env` (RAG, channels, news, YouTube, summaries, acquisition, AutoMod, Feature Flags, SLA, etc.).

**`bot/main.py`** — validate secrets → init OpenAI / ChromaDB → register Cogs → guild-level slash sync (commands visible soon after restart) → Discord login.

Common core config examples:

| Setting | Description |
|---|---|
| `TARGET_CHANNEL_IDS` | Channels RAG listens on |
| `CONFIDENCE_THRESHOLD` | Confidence threshold (default 7) |
| `RESPOND_MODE` | `auto` / `review` / `questions` / `mention_only` |
| `NEWS_FEED_ENABLED` / `NEWS_CHANNEL_IDS` | Jin10 push |
| `DAILY_SUMMARY_*` / `WEEKLY_SUMMARY_*` | Daily/weekly summary timing and channels |
| `YOUTUBE_MONITOR_ENABLED` | New-video monitoring |
| `AUTO_MOD_ENABLED` | Auto moderation |
| `WELCOME_FLOW_ENABLED` | New-member welcome and drip |

---

### Ingestion layer

#### `ingestion/preprocess.py` — preprocessing

Discord export JSON → Q&A pair extraction → merge consecutive messages → text cleanup → token chunking.

#### `ingestion/ingest.py` — vectorization

Batch Embedding → write ChromaDB; supports incremental (no duplicates).

#### `ingestion/analyze_style.py` — style analysis

Stats on length, common phrases, emoji, etc. → `data/style_profile.txt` for RAG prompts.

#### `ingestion/ingest_youtube.py` — YouTube ingest

Captions preferred; otherwise `yt-dlp` + `ffmpeg` + Whisper. Binaries may live under `.venv/Scripts/`; code resolves full paths and does not rely on system PATH. PDF ingest also supported (`ingest_pdf.py`).

---

### Message handling and RAG

#### `bot/listener.py` — message orchestrator

1. **Filter**: bots, excluded channels, empty content, etc.  
2. **AutoMod / Topic Guard**: spam and off-topic first  
3. **Intent**: purchase intent → acquisition CTA (may skip RAG)  
4. **Rate limit**: per-user cooldown + global cap; VIP roles exempt  
5. **Multimodal**: voice notes Whisper; images Vision  
6. **Queue**: `asyncio.Queue` serial processing to avoid API storms  
7. **Owner post learning**, offline backfill, Thread context, reaction feedback collection

#### `bot/rag.py` — retrieve and generate

Retrieve: embedding → Top-K → distance filter → dedupe.  
Generate: style guide + context + (optional) negatives / Session summary → LLM → parse `CONFIDENCE`.  
Includes embedding cache, retries, and reliability instrumentation.

#### `bot/confidence.py` — routing

Typical triple condition (all configurable): has context, best distance close enough, confidence ≥ threshold. All must pass for auto-send; otherwise review. Can stack with Clarification and Guardrails.

---

### Review and learning loop

#### `bot/review.py` + `bot/review_queue.py`

Low-confidence drafts DM Owner: `Approve` / `Edit` / `Reject`. Approve may ingest; Reject / Edit enter negatives or learning queue. Queue has expiry cleanup to avoid false SLA “backlog” alerts.

#### `bot/feedback.py` / `bot/feedback_learning.py`

👍👎 record satisfaction; periodically summarize Top N knowledge gaps to drive KB backfill.

---

### Content and news automation

#### `bot/news_feed.py` — Jin10 flash news

- Default ~30s poll; `NEWS_IMPORTANT_ONLY` can push only important flashes  
- Dedupe, ad filter; important messages use Embeds  
- **Every `on_ready` (including reconnect) backfills** the offline window (default 24h, max 50 important)  
- **Advance `last_id` only after successful post** — avoids misses  

#### `bot/daily_summary.py` / `bot/weekly_summary.py`

- Scan configured channels for owner messages and replies; GPT Embed; optional @everyone  
- Daily: prevent same-day double send (early timer wake will not double-post)  
- Weekly: read failures retry and catch-up so “no messages” is not a false miss  

#### `bot/youtube_monitor.py`

- Timed channel RSS check; new videos can schedule lesson posts, ingest, summarize to `YOUTUBE_SUMMARY_CHANNELS`  
- Transcription failure can still send a new-video notice; `/resend_summary` can backfill summaries (auto KB / Whisper ingest / title fallback)  
- Summaries may attach acquisition CTA buttons  

#### `bot/views_summary.py` + `/views`

Server-wide scan of recent owner posts; short views summary posted to the current channel (no @everyone).

## 5. Key technical concepts

### Embedding (vector embeddings)

Text → high-dimensional vectors; semantically similar text has nearby vectors. This project defaults to OpenAI embedding models.

### ChromaDB

Local persistent vector store (`chromadb_store/`), similarity search over historical posts / video transcripts, etc.

### Cosine Distance

| Distance | Meaning |
|---|---|
| 0.0 | Nearly identical |
| ~0.3 | Highly related |
| ~0.6 | Marginally related |
| ≥0.8 | Usually filtered out |

### RAG

Retrieve trusted context first, then generate — reduces “pure model hallucination”.

### Feature Flag / Canary

New capabilities can enable in a subset of channels first, then go full after stability is proven.

## 6. Cost structure

| Item | Magnitude | Notes |
|---|---|---|
| Historical ingest (one-time / incremental) | Relatively low | Embedding billed by token |
| Each text Q&A | ~$0.001 class | Retrieval + GPT-4o-mini |
| Image Vision / voice Whisper | Higher | Per call / per duration |
| Jin10 polling | Near $0 | External HTTP; no OpenAI |
| Daily/weekly summaries, video digests | Medium | Depends on scanned volume and model |
| AutoMod semantic ban words / Topic Guard | Medium | Embeddings or GPT classification |

Actual cost scales with question volume, multimodal share, and summary channel count. Rate limits and VIP exemption help control spend.

## 7. Safety and reliability design

| Mechanism | Notes |
|---|---|
| Triple confidence checks | Lower chance of nonsense in public channels |
| Owner review queue | Uncertain content DMs first |
| Rate limit + VIP | Anti-abuse and cost control |
| AutoMod / Topic Guard | Spam, scams, off-topic |
| Guardrails | all-in / guaranteed returns → force review or disclaimer |
| Secrets only in `.env` | Not committed to Git |
| News `last_id` advances after success | Avoid offline misses |
| Daily dedupe / weekly retry catch-up | Avoid misses or double sends |
| SLA alerts | Latency, error rate, backlog notify Owner |
| Review button anti-double / timeout | Prevent double posts and zombie tasks |

## 9. Everyday command cheat sheet

```powershell
# Activate virtual environment
.venv\Scripts\Activate.ps1

# Start Bot
python -m bot.main

# Ingest Discord data (incremental)
python -m ingestion.ingest

# Ingest YouTube
```

## 11. Environment install and initialization

For a quick start see [`SETUP_AND_TEST.md`](../getting-started/SETUP_AND_TEST.md).

### Prerequisites

| Component | Requirement | Verify |
|------|------|----------|
| Python | 3.11+ | `python --version` |
| Node.js | 18+ (frontends) | `node --version` |
| FFmpeg / deno | Recommended for YouTube Whisper path | May live under `.venv\Scripts\` |
| Discord Bot Token | Developer Portal | — |
| OpenAI API Key | OpenAI | — |
| Git | Version control | `git --version` |

### Install steps

```powershell
# 1. System tools (example)
winget install --id Python.Python.3.11 -e
winget install --id Gyan.FFmpeg -e

# 2. Clone and enter project
git clone <your-repo-url>
cd treeProjectDiscordBot

# 3. Virtual environment
python -m venv .venv
.venv\Scripts\Activate.ps1

# 4. Dependencies
pip install -r requirements.txt

# 5. Config
Copy-Item .env.example .env
# Required: DISCORD_BOT_TOKEN, OPENAI_API_KEY, OWNER_USER_ID, TARGET_CHANNEL_IDS

# 6. Ingest + (optional) style
python -m ingestion.ingest
python -m ingestion.analyze_style

# 7. Start
python -m bot.main
```

### Rebuild the virtual environment after moving machines (Windows)

Do not copy an old `.venv`. Rebuild with the **`py` launcher**:

```powershell
Remove-Item -Recurse -Force .venv
py -m venv .venv
.venv\Scripts\Activate.ps1
python --version
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m bot.main
```

If `Activate.ps1` is blocked:

```powershell
Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
```
